# 토끼네 자리 🐰

모바일 세로 화면용 HTML5 논리 퍼즐. 각 **색 자리(영역)**·**가로줄**·**세로줄**에
토끼를 한 마리씩 놓되, 토끼끼리는 **대각선을 포함해 어디로도 붙어 앉을 수 없다**.
(Queens / Star-Battle 계열)

## 바로 해보기

- `index.html` 을 브라우저에서 열면 끝. (퍼즐 데이터가 파일 안에 내장돼 있어 서버 없이도 동작)
- 정적 서버로 띄우면 `puzzles.json` 을 먼저 불러오므로, 레벨만 따로 갈아끼울 수 있다.
  ```bash
  python3 -m http.server 8000     # http://localhost:8000
  ```

## GitHub Pages 배포

배포 주소: **https://joon-bot.github.io/meowdoku-game/**

`.github/workflows/deploy-pages.yml` 이 `main` 또는 작업 브랜치에 push 될 때마다
퍼즐을 검증하고 `index.html` + `puzzles.json` 을 게시한다.

### 최초 1회는 수동 설정이 필요하다

워크플로의 `GITHUB_TOKEN` 에는 **Pages 사이트를 생성할 권한이 없다**
(저장소 관리자 권한이 필요하다). 그래서 처음 한 번은 사람이 켜줘야 한다.

1. 레포 **Settings → Pages**
2. **Source** 를 `GitHub Actions` 로 선택

> ⚠️ **이 레포는 비공개(private)다.** 비공개 레포의 Pages 는 **GitHub Pro 이상**에서만 동작한다.
> 무료 플랜이라면 레포를 공개로 바꾸거나 플랜을 올려야 한다.
>
> 그리고 어느 쪽이든 **게시된 페이지 자체는 누구나 접근 가능**하다.
> (접근 제한이 걸린 Pages 는 Enterprise 기능이다.) 레포가 비공개면 소스만 가려질 뿐,
> 게임 URL 은 링크를 아는 사람 누구에게나 열린다.

### Actions 없이 배포하는 방법

워크플로를 쓰지 않고 브랜치에서 바로 게시해도 된다. 게임이 레포 루트에 있고
`.nojekyll` 도 있어서 추가 설정이 필요 없다.

- Settings → Pages → Source: **Deploy from a branch** → 브랜치 선택 → 폴더 `/ (root)`

이 경우 배포 전 퍼즐 검증은 돌지 않는다.

## 조작

| 동작 | 결과 |
| --- | --- |
| 탭 1회 | ✕ 표시 (여기 아님 메모) |
| 탭 2회 | 🐰 토끼 배치 |
| 탭 3회 | 빈칸 |
| **빈칸에서 끌기** | 지나간 빈칸을 한 번에 ✕ 로 채우기 |
| **✕ 에서 끌기** | 지나간 ✕ 를 한 번에 지우기 |
| **두 손가락** | 보드 이동 + 핀치 확대/축소 (＋／－ 버튼도 있음) |

> 끌기의 방향(그리기/지우기)은 **끌기를 시작한 칸**이 정한다. 토끼와 잠긴 칸은
> 어느 쪽이든 건드리지 않는다.
>
> 한 손가락 끌기를 ✕ 칠하기에 내줬기 때문에 **보드 이동은 두 손가락**이다.

- ✕ 메모는 **흰색**(어두운 테두리를 깔아 어떤 영역 색 위에서도 읽힌다).
- 하트 3개. **토끼가 앉을 수 없는 자리를 고르면 토끼가 놓이지 않는다.**
  대신 그 칸이 **빨간 ✕ 로 잠기고** 하트가 하나 줄며, 부딪힌 토끼가 잠깐 붉게 깜빡인다.
- 잠긴 칸은 눌러도 바뀌지 않는다. 다만 **잠글 이유가 된 토끼를 치우면 자동으로 풀린다** —
  안 그러면 되돌리기 후에도 정답 칸이 막힌 채 남아 판이 풀리지 않게 된다.
- 하트를 모두 쓰면 게임 오버, 완성하면 축하 연출 후 다음 레벨로.
- 진행 상황(클리어 기록·진행 중인 판·하트·시간)은 `localStorage` (`tokkine-jari/v1`) 에 저장된다.

## 힌트

힌트 버튼은 **지금 논리적으로 확정 가능한 다음 한 수**를 이유와 함께 알려준다.
찍기(백트래킹)로 답을 훔쳐보는 게 아니라, 아래 규칙을 순서대로 적용해 사람이 따라갈 수 있는
추론 한 단계를 뽑아낸다.

| 단계 | 규칙 |
| --- | --- |
| T0 | 어떤 영역/줄에 남은 후보가 한 칸뿐 → 그 칸에 토끼 확정 |
| T1 | 한 영역의 후보가 모두 한 줄에 몰림(또는 그 반대) → 나머지 칸 제외 |
| T2 | k개의 줄이 k개의 영역만 나눠 쓰는 경우 (k=2,3) → 나머지 칸 제외 |
| T3 | 그 칸에 놓으면 어떤 영역/줄이 자리를 전부 잃음 → 그 칸 제외 |

플레이어가 **정답이 아닌 칸에 토끼를 놓은 상태**라면 힌트는 먼저 그 칸을 짚어준다.

> 힌트는 현재 무료다. 광고 연동은 `HINT_CONFIG` (index.html) 한 곳만 바꾸면 되도록 분리해 뒀다.
> ```js
> const HINT_CONFIG = { free: true, onConsume() { /* 광고 연동 지점 */ } };
> ```

## 토끼 그림

토끼는 `assets/` 의 PNG 를 쓴다. 나머지 그림(✕·당근·발자국)은 인라인 SVG 다.

| 파일 | 쓰이는 곳 |
| --- | --- |
| `assets/rabbit.png` | 보드 타일에 놓이는 기본 포즈 (칸의 80%) |
| `assets/rabbit_jump.png` | 클리어 순차 점프, 클리어 화면 |
| `assets/rabbit_sad.png` | 당근이 줄 때 보드 중앙 연출(0.8초), 게임 오버 |
| `assets/rabbit_think.png` | 예비 — 갸웃 (힌트/튜토리얼용) |
| `assets/rabbit_sleep.png` | 예비 — 자는 포즈 (로딩 화면용) |

배경 제거는 `tools/cutout.py` 가 한다. 단순 색 키로는 안 되는데,
**배경(249,237,213)과 토끼 몸통 크림색의 거리가 2~16 이라 배경 노이즈(최대 5.5)와
구간이 겹치기 때문**이다. 몸 한가운데가 배경과 똑같은 색인 지점도 있어서, 어떤
문턱값을 잡아도 몸통에 구멍이 뚫리거나 배경이 남는다. 그래서 색이 아니라 **실루엣을
닫아서** 푼다 — 윤곽 후보를 부풀려 끊긴 곳을 잇고, 바깥에서 못 닿는 영역을 내부로
간주해 채운 뒤, 부풀린 만큼 다시 깎는다(모폴로지 클로징).

```bash
python3 tools/cutout.py 원본.png assets/rabbit.png
```

## 그림 교체

교체 지점은 **`ASSETS` 상수 한 곳**이다.

```js
const ASSETS = {
  rabbit: 'assets/rabbit.png',        // 기본 — 보드 타일
  happy:  'assets/rabbit_jump.png',   // 클리어 (점프)
  tired:  'assets/rabbit_sad.png',    // 실수·게임 오버 (시무룩)
  mark:   null,                       // ✕ 메모   (null = 내장 SVG)
  locked: null,                       // 잠긴 칸
  face:   null,                       // 배치 카운터 아이콘
  paw:    null,                       // 자동배치 부스터 아이콘
  carrot: null,                       // 난이도·목숨 아이콘
};
```

`null` 이면 내장 SVG 를 쓴다. 경로를 채우면 그 종류만 `<img>` 로 바뀐다.
게임 로직은 `RabbitArt.html(kind, mood)` 만 호출하므로 다른 곳은 손댈 필요가 없다.
칸에 들어가는 그림은 **정사각형·투명 배경**을 권장한다 (칸의 78% 크기로 그려진다).

## 난이도의 정의

난이도는 **추론 깊이 하나로만** 매긴다. 영역 크기 분포와는 완전히 분리돼 있어서,
어려움 레벨에 1칸 영역이 나올 수도 있고 쉬움 레벨에 하나도 없을 수도 있다.

```
깊이 = (필요한 최고 규칙 단계 × 8) + (배치가 아닌 "지우기" 추론 수) + 첫 확정까지의 수
```

| 난이도 | 깊이 | 당근 |
| --- | --- | --- |
| 쉬움 | ≤ 6 | 🥕 |
| 보통 | 7 ~ 13 | 🥕🥕 |
| 어려움 | ≥ 14 | 🥕🥕🥕 |

### 영역 크기 분포

크기는 난이도와 무관하게 **극단적인 불균등을 허용**한다.

- 보드의 **30~40%** 를 차지하는 거대 영역 1개
- **1~2칸짜리 미니 영역 0~3개** (무작위)
- 나머지는 2칸 이상

이 프로필은 영역 성장부터 유일해 수선까지 전 과정의 불변식으로 지켜진다.

## 감각 피드백 (juice)

모든 연출은 **transform / opacity 만** 애니메이션한다 (레이아웃·페인트 유발 속성 없음).
`prefers-reduced-motion: reduce` 를 켠 사용자에게는 전부 걷어낸다.

| 상황 | 연출 |
| --- | --- |
| 토끼 배치 | 위에서 떨어져 눌렸다 통통 튀는 스쿼시&스트레치 + 진동 + 낮고 포근한 두 음 |
| ✕ 메모 / 지우기 | 미세한 스케일 팝 / 쪼그라들며 사라짐 + 짧은 틱 |
| 규칙 위반 | 화면 미세 흔들림 + 부드러운 낮은 톤 + 진동 |
| 클리어 | 토끼들이 90ms 간격으로 차례차례 귀 흔들며 점프 + 상승 아르페지오 + 색종이 |
| 레벨 전환 | 보드가 왼쪽으로 밀려나고 다음 판이 오른쪽에서 들어옴 |

효과음은 오디오 파일 없이 **Web Audio 로 그때그때 생성**한다 (`Sfx`).
브라우저 자동재생 정책 때문에 AudioContext 는 첫 탭에서 깨운다.
HUD 의 스피커 버튼으로 끄고 켤 수 있고, 상태는 저장된다 — **음소거는 진동도 함께 끈다.**

## 튜토리얼

첫 실행이면 타이틀 대신 **고정 5×5 예제**로 바로 들어간다.
**읽지 않아도 배우게** 만드는 게 목표라, 설명은 보드 위 한 줄뿐이고 나머지는 전부 시각 요소다.

- **눌러야 할 칸 하나만** 밝게 pulse 하고 나머지는 어둡게 깔린다. 그 위에 손가락 아이콘이
  두 번 두드리는 애니메이션으로 떠 있다.
- **행동해야 진행된다.** 실제로 그 칸을 탭해서 토끼를 놓아야 다음 단계로 넘어간다.
- **틀린 칸을 눌러도 벌점이 없다.** 부드럽게 흔들려 거부하고, 정답 칸이 더 강하게 반짝인다.
- **규칙은 행동 직후에 보여준다.** 토끼를 놓는 순간 그 행·열에 빛줄기가 스윽 지나가고
  그 칸들이 차례로 ✕ 로 깔린다("이 줄엔 이제 못 와요"). 이어서 대각선 네 칸이 잠깐
  붉게 떴다 사라진다("대각선도 붙으면 안 돼요").
- 마지막 수를 놓으면 **"이제 진짜 시작!"** 연출과 함께 레벨 1 로 넘어간다.

건너뛰기 버튼은 항상 떠 있다. 예제는 해가 유일하고 5수 전부가 논리적으로 강제되는 수이며,
`tools/build.mjs` 가 빌드할 때마다 유일성과 각 단계의 정답 일치를 검증한다.
타이틀 → 게임 방법 → **튜토리얼 다시** 로 언제든 다시 볼 수 있다.

## 화면

- **타일형 보드** — 영역 경계선이 없다. 모든 칸이 독립 타일이고(모서리 20%, 간격 7%),
  영역 구분은 **오직 색으로만** 한다. 보드는 흰색 라운드 카드, 페이지는 웜 크림.
- **상단 HUD** — 뒤로가기 / 레벨 번호 + 난이도(당근 1~3개) / 설정
- **그 아래** — 토끼 배치 카운터(🐰 n/N), 점수, 목숨(당근 3개). **타이머 없음**
- **규칙 알약 칩 3개 상시 표시** — "색깔 자리마다 토끼 1마리" / "행·열마다 1마리" /
  "토끼끼리 붙기 금지" (좁은 화면에서는 문구를 줄바꿈해 그대로 보여 준다)
- **하단 플로팅 원형 버튼 2개** — 힌트(전구 + 남은 개수), 자동배치 부스터(발자국 + 남은 개수)
- 되돌리기 · 다시 놓기 · 확대/축소 · 소리 · 튜토리얼 다시는 **설정 시트**에 모아 두었다.

## 점수

**남은 당근과 아껴 둔 힌트**가 전부다. 시간은 보지 않는다 (그래서 타이머도 없다).

```
점수 = 칸 수 × 10  +  남은 당근 × 150  +  안 쓴 힌트 × 100  +  안 쓴 자동배치 × 60
```

상단 HUD 에 실시간으로 표시되고, 클리어 화면에도 나온다. 레벨별 최고 점수가 저장되며,
한 번도 안 틀리고 힌트도 안 쓰면 **만점**이다.

## 색 배정

팔레트는 **"토끼네 마당" — 봄 텃밭의 자연색 10가지**다.
새싹 연두 · 볏짚 노랑 · 진달래 핑크 · 맑은 하늘 · 라일락 · 호박 주황 · 이끼 세이지 ·
감 로즈 · 흙 브라운 · 진한 잎초록. 채도는 부드럽게 누르되 **명도는 확실히 벌려** 두었다.

적록색약이 있으면 초록·노랑·주황·빨강이 전부 노란 계열로 뭉개지므로, 그 색들이
**밝기 사다리** 위에 흩어져 있어야 층으로라도 갈린다. 하늘·라일락은 파랑 계열이라
적록색약에서도 색상 자체가 남는다.

영역 색은 고정이 아니라 **레벨마다 그래프 컬러링으로 배정**된다.

1. 이웃이 많은 영역부터 "이미 정해진 이웃들과 가장 멀리 떨어진 색"을 고른다
2. **가장 약한 이웃 쌍의 거리를 최대화**하는 방향으로 몇 바퀴 더 다듬는다
3. 1단계에서 확보한 거리 하한을 **깨지 않는 선에서만** 색을 고루 펼친다
   (같은 색이 여러 영역에 반복되면 인접하지 않더라도 판을 읽기 어렵다)

색 거리는 단순 RGB 차이가 아니라 **Lab 공간의 ΔE**로 재고, 정상 시야뿐 아니라
**적록색약(2형·1형) 시뮬레이션 결과까지 계산해 그중 가장 가까워지는 값**을 그 쌍의
거리로 삼는다. 즉 색약이 있어도 구분되는 조합만 이웃으로 배정된다.

> 청황색약(tritan)은 파랑–노랑 축이 무너지는데, 그 축은 적록색약이 유일하게 보존하는
> 축이기도 하다. 파스텔 명도 범위 안에서 둘을 동시에 만족시킬 수 없어, 훨씬 흔한
> 적록 쪽(남성 약 8%)을 택했다. 청황색약은 0.01% 수준이고, 영역 경계선이 색과
> 무관한 구조 단서로 남는다.

여기에 더해 **모든 칸에 옅은 격자선**을 깔아 영역 안에서도 칸 단위가 항상 읽히게 했고,
영역 경계는 그보다 조금 굵은 선으로 형태만 잡아준다.

## 레벨 다시 만들기

생성(느림)과 레벨 순서 결정(빠름)이 분리돼 있다. 커브만 바꿔 다시 돌리는 건 순식간이다.

```bash
node tools/generate-puzzles.mjs      # 퍼즐 풀 생성 -> puzzles-pool.json (오래 걸린다)
node tools/curate-levels.mjs         # 풀에서 레벨 순서 결정 -> puzzles.json
node tools/build.mjs                 # 검증 + index.html 내장 사본 갱신
```

생성기는 다음을 **모든 레벨에 대해 보장**한다.

1. 해가 **정확히 하나** — 무작위로 영역을 키운 뒤, 가짜 해가 나오면 칸 하나의 소속 영역을
   바꿔 그 해를 깨뜨리는 수선(repair) 과정을 반복한다. 정답 칸은 절대 옮기지 않고
   난이도 프로필(min/max)도 매 수선마다 검사하므로, 정답과 난이도 규칙이 함께 유지된다.
2. **찍기 없이 논리만으로 풀린다** — 규칙 T0~T3 로 끝까지 풀리지 않으면 채택하지 않는다.
   덕분에 힌트가 어느 상황에서도 막히지 않는다.
3. 모든 영역은 **상하좌우로 연결**돼 있다.

`tools/build.mjs` 는 생성기와 독립적으로 유일성·연결성·난이도 규격·튜토리얼을 다시
검사하므로, `puzzles.json` 을 손으로 고친 경우에도 안전망이 된다.

### 레벨 커브

`curate-levels.mjs` 가 풀에서 고른다. 쉬움의 기준은 추론 수(적을수록 쉬움),
1칸 영역 개수(많을수록 쉬움), 첫 확정까지의 수, 가장 큰 영역 크기(작을수록 눈이 편함).

- **첫 5레벨은 5×5 중에서도 가장 쉬운 것들** — 전부 추론 5수, 막히는 구간 0, 1칸 영역 2개
- 그 뒤로는 크기 순으로 올라가되, 같은 크기 안에서는 쉬운 것부터
