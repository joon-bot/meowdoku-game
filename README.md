# 토끼네 자리 🐰

모바일 세로 화면용 HTML5 논리 퍼즐. 각 **색 자리(영역)**·**가로줄**·**세로줄**에
토끼를 한 마리씩 놓되, 토끼끼리는 **대각선을 포함해 어디로도 붙어 앉을 수 없다**.
(Queens / Star-Battle 계열)

## 바로 해보기

- `index.html` 을 브라우저에서 열면 끝. (퍼즐 데이터가 파일 안에 내장돼 있어 서버 없이도 동작)
- 정적 서버로 띄우면 `puzzles.json` 을 먼저 불러오므로, 레벨만 따로 갈아끼울 수 있다.
  ```bash
  python3 -m http.server 8000     # http://localhost:8000
  ```

## GitHub Pages 배포

배포 주소: **https://joon-bot.github.io/meowdoku-game/**

`.github/workflows/deploy-pages.yml` 이 `main` 또는 작업 브랜치에 push 될 때마다
퍼즐을 검증하고 `index.html` + `puzzles.json` 을 게시한다.

### 최초 1회는 수동 설정이 필요하다

워크플로의 `GITHUB_TOKEN` 에는 **Pages 사이트를 생성할 권한이 없다**
(저장소 관리자 권한이 필요하다). 그래서 처음 한 번은 사람이 켜줘야 한다.

1. 레포 **Settings → Pages**
2. **Source** 를 `GitHub Actions` 로 선택

> ⚠️ **이 레포는 비공개(private)다.** 비공개 레포의 Pages 는 **GitHub Pro 이상**에서만 동작한다.
> 무료 플랜이라면 레포를 공개로 바꾸거나 플랜을 올려야 한다.
>
> 그리고 어느 쪽이든 **게시된 페이지 자체는 누구나 접근 가능**하다.
> (접근 제한이 걸린 Pages 는 Enterprise 기능이다.) 레포가 비공개면 소스만 가려질 뿐,
> 게임 URL 은 링크를 아는 사람 누구에게나 열린다.

### Actions 없이 배포하는 방법

워크플로를 쓰지 않고 브랜치에서 바로 게시해도 된다. 게임이 레포 루트에 있고
`.nojekyll` 도 있어서 추가 설정이 필요 없다.

- Settings → Pages → Source: **Deploy from a branch** → 브랜치 선택 → 폴더 `/ (root)`

이 경우 배포 전 퍼즐 검증은 돌지 않는다.

## 파일 구성

| 파일 | 설명 |
| --- | --- |
| `index.html` | 게임 전체 (HTML + CSS + JS 단일 파일). 퍼즐 데이터 내장 사본 포함 |
| `puzzles.json` | 실제 레벨 20개 (5×5 ~ 10×10), 순서까지 확정된 것 |
| `puzzles-retired.json` | 스테이지에서 뺀 6판 (11×11 ~ 13×13). 게임은 안 읽고 검사만 한다 |
| `puzzles-pool.json` | 생성기가 뽑아둔 퍼즐 풀 (레벨보다 많이 만들어 둔다) |
| `tools/generate-puzzles.mjs` | 퍼즐 생성기 (풀 생성) |
| `tools/curate-levels.mjs` | 풀에서 레벨 순서·난이도 커브 결정 |
| `tools/build.mjs` | 퍼즐 검증 + `index.html` 내장 사본 갱신 |
| `tools/check-colors.mjs` | 영역 배색 검증 (색 중복 · 대각 동색 · 인접 ΔE) |
| `tools/check-generator.mjs` | 무한 마당 생성기 검증 (워커 소스 자기완결성 + 판 품질) |

## 조작

| 동작 | 결과 |
| --- | --- |
| **한 번 탭** | ✕ 메모 켜기 / 끄기 |
| **빠르게 두 번 탭** | 🐰 토끼 놓기 (✕ 를 거치지 않는다) |
| 토끼를 탭 | 치우기 |
| **빈칸에서 끌기** | 지나간 빈칸을 한 번에 ✕ 로 채우기 |
| **✕ 에서 끌기** | 지나간 ✕ 를 한 번에 지우기 |
| **두 손가락** | 보드 이동 + 핀치 확대/축소 (＋／－ 버튼도 있음) |

> 끌기의 방향(그리기/지우기)은 **끌기를 시작한 칸**이 정한다. 토끼와 잠긴 칸은
> 어느 쪽이든 건드리지 않는다.
>
> 한 번 탭은 더블탭 판정을 위해 260ms 뒤에 ✕ 로 굳는다. 그동안 다른 칸을 누르거나
> 끌기로 넘어가면 대기 중이던 탭은 즉시 ✕ 로 확정된다.
>
> 한 손가락 끌기를 ✕ 칠하기에 내줬기 때문에 **보드 이동은 두 손가락**이다.

- ✕ 메모는 타일 색 위에 얹는 **굵은 흰색 스트로크**(칸의 14%).
- 토끼는 **정답 칸인지로 즉시 판정**한다. 해가 유일하므로 정답이 아닌 칸은 언제
  눌러도 틀린 칸이다. 틀리면 토끼가 놓이지 않고 **당근이 하나 줄며 그 칸은 ✕ 로 잠긴다.**
- 잠금은 **영구적**이다 (되돌리기로도 풀리지 않는다). "여기는 아니었다"는 표시가 판에
  남아야 다음 추론에 쓸 수 있기 때문이다. 같은 칸을 또 눌러도 당근이 더 줄지는 않는다.
- 당근을 모두 쓰면 게임 오버, 완성하면 축하 연출 후 다음 레벨로.
- 진행 상황(클리어 기록·진행 중인 판·하트·시간)은 `localStorage` (`tokkine-jari/v1`) 에 저장된다.

## 힌트

힌트 버튼은 **지금 논리적으로 확정 가능한 다음 한 수**를 이유와 함께 알려준다.
찍기(백트래킹)로 답을 훔쳐보는 게 아니라, 아래 규칙을 순서대로 적용해 사람이 따라갈 수 있는
추론 한 단계를 뽑아낸다.

| 단계 | 규칙 |
| --- | --- |
| T0 | 어떤 영역/줄에 남은 후보가 한 칸뿐 → 그 칸에 토끼 확정 |
| T1 | 한 영역의 후보가 모두 한 줄에 몰림(또는 그 반대) → 나머지 칸 제외 |
| T2 | k개의 줄이 k개의 영역만 나눠 쓰는 경우 (k=2,3) → 나머지 칸 제외 |
| T3 | 그 칸에 놓으면 어떤 영역/줄이 자리를 전부 잃음 → 그 칸 제외 |

플레이어가 **정답이 아닌 칸에 토끼를 놓은 상태**라면 힌트는 먼저 그 칸을 짚어준다.

> 힌트는 현재 무료다. 광고 연동은 `HINT_CONFIG` (index.html) 한 곳만 바꾸면 되도록 분리해 뒀다.
> ```js
> const HINT_CONFIG = { free: true, onConsume() { /* 광고 연동 지점 */ } };
> ```

## 토끼 그림

토끼는 `assets/` 의 PNG 를 쓴다. 나머지 그림(✕·당근·발자국)은 인라인 SVG 다.

| 파일 | 쓰이는 곳 |
| --- | --- |
| `assets/rabbit.png` | 보드 타일에 놓이는 기본 포즈 (칸의 80%) |
| `assets/rabbit_jump.png` | 클리어 순차 점프, 클리어 화면 |
| `assets/rabbit_sad.png` | 당근이 줄 때 보드 중앙 연출(0.8초), 게임 오버 |
| `assets/rabbit_think.png` | 예비 — 갸웃 (힌트/튜토리얼용) |
| `assets/rabbit_sleep.png` | 예비 — 자는 포즈 (로딩 화면용) |

배경 제거는 `tools/cutout.py` 가 한다. 단순 색 키로는 안 되는데,
**배경(249,237,213)과 토끼 몸통 크림색의 거리가 2~16 이라 배경 노이즈(최대 5.5)와
구간이 겹치기 때문**이다. 몸 한가운데가 배경과 똑같은 색인 지점도 있어서, 어떤
문턱값을 잡아도 몸통에 구멍이 뚫리거나 배경이 남는다. 그래서 색이 아니라 **실루엣을
닫아서** 푼다 — 윤곽 후보를 부풀려 끊긴 곳을 잇고, 바깥에서 못 닿는 영역을 내부로
간주해 채운 뒤, 부풀린 만큼 다시 깎는다(모폴로지 클로징).

```bash
python3 tools/cutout.py 원본.png assets/rabbit.png
```

## 그림 교체

교체 지점은 **`ASSETS` 상수 한 곳**이다.

```js
const ASSETS = {
  rabbit: 'assets/rabbit.png',        // 기본 — 보드 타일
  happy:  'assets/rabbit_jump.png',   // 클리어 (점프)
  tired:  'assets/rabbit_sad.png',    // 실수·게임 오버 (시무룩)
  mark:   null,                       // ✕ 메모   (null = 내장 SVG)
  locked: null,                       // 잠긴 칸
  face:   null,                       // 배치 카운터 아이콘
  paw:    null,                       // 자동배치 부스터 아이콘
  carrot: null,                       // 난이도·목숨 아이콘
};
```

`null` 이면 내장 SVG 를 쓴다. 경로를 채우면 그 종류만 `<img>` 로 바뀐다.
게임 로직은 `RabbitArt.html(kind, mood)` 만 호출하므로 다른 곳은 손댈 필요가 없다.
칸에 들어가는 그림은 **정사각형·투명 배경**을 권장한다 (칸의 78% 크기로 그려진다).

## 난이도의 정의

난이도는 **추론 깊이 하나로만** 매긴다. 영역 크기 분포와는 완전히 분리돼 있어서,
어려움 레벨에 1칸 영역이 나올 수도 있고 쉬움 레벨에 하나도 없을 수도 있다.

```
깊이 = (필요한 최고 규칙 단계 × 8) + (배치가 아닌 "지우기" 추론 수) + 첫 확정까지의 수
```

| 난이도 | 깊이 | 당근 |
| --- | --- | --- |
| 쉬움 | ≤ 6 | 🥕 |
| 보통 | 7 ~ 13 | 🥕🥕 |
| 어려움 | ≥ 14 | 🥕🥕🥕 |

### 영역 크기 분포

크기는 난이도와 무관하게 **극단적인 불균등을 허용**한다.

- 보드의 **30~40%** 를 차지하는 거대 영역 1개
- **1~2칸짜리 미니 영역 0~3개** (무작위)
- 나머지는 2칸 이상

이 프로필은 영역 성장부터 유일해 수선까지 전 과정의 불변식으로 지켜진다.

> 위 숫자는 **스테이지 20판**(`tools/generate-puzzles.mjs`)의 값이다. 무한 마당은
> 같은 생성기를 쓰되 이 프로필을 난이도 손잡이로 삼아 레벨마다 지시한다 —
> [난이도 축은 크기가 아니라 구조다](#난이도-축은-크기가-아니라-구조다) 참고.

## 감각 피드백 (juice)

모든 연출은 **transform / opacity 만** 애니메이션한다 (레이아웃·페인트 유발 속성 없음).
`prefers-reduced-motion: reduce` 를 켠 사용자에게는 전부 걷어낸다.

| 상황 | 연출 | 타이밍 |
| --- | --- | --- |
| 토끼 배치 | 방석 + 팝 + 링 파동 + 반짝임 + 진동 + 낮고 포근한 두 음 | 아래 표 참고 |
| ✕ 메모 / 지우기 | 미세한 스케일 팝 / 쪼그라들며 사라짐 + 짧은 틱 | `190ms` / `160ms` |
| 끌기로 ✕ 여러 칸 | 지나간 칸이 **차례로** 팝 (소리·진동도 같이 밀린다) | 칸 간격 `30ms`, 밀림 상한 `300ms` |
| 규칙 위반 | 화면 미세 흔들림 + 부드러운 낮은 톤 + 진동 | `400ms` |
| 클리어 | 아래 안무 참고 | — |

끌기 간격은 **밀린 만큼만** 준다. 손가락이 느려서 이미 30ms 넘게 벌어져 있으면 지연 0,
빠르게 훑어 한 프레임에 여러 칸이 들어오면 그때만 줄을 세운다. 그래서 천천히 그으면
즉각 반응하고, 빠르게 그으면 물결처럼 따라온다.

### 토끼 배치 — 네 겹

배치가 게임에서 제일 많이 반복되는 동작인데, 예전에는 `200ms` 스케일 팝 하나뿐이었다.
오버슈트를 이징(`cubic-bezier(.34,1.56,…)` 이 1 을 10% 넘어간다)에 맡겨서 티가 안 났고,
무엇보다 **크림색 토끼가 연두·분홍 타일 위에서 윤곽이 묻혔다** — 놓았는지 아닌지 헷갈린다.
그래서 네 겹으로 나눴다.

| 겹 | 무엇 | 값 |
| --- | --- | --- |
| **방석** | 놓인 토끼 뒤에 **상시** 깔리는 반투명 흰 원. 색을 안 건드리고 토끼와 타일 사이에 판을 한 장 끼워 어떤 배색에서도 같은 대비를 만든다 | 지름 = 칸의 `80%` (`inset:10%`), `rgba(255,255,255,.88)`, 그림자 `0 2px 6px rgba(120,95,75,.22)` + 안쪽 테 `0 0 0 1px rgba(255,255,255,.65)` |
| **팝** | 오버슈트를 이징이 아니라 **키프레임에 못박았다** | `240ms` — `scale .40 → 1.20(25%) → .95(55%) → 1.03(78%) → 1.0` <br> 방석은 같은 길이로 덜 튄다 (`.30 → 1.12 → .97 → 1.0`) |
| **링 파동** | 칸 중심에서 흰 링이 한 번 퍼지며 사라진다 | `300ms` — `scale .34 → 1.6`, `opacity .95 → .85(45%) → 0`, 테 `3px` |
| **반짝임** | 작은 알갱이 4개가 위쪽 부채꼴로 튀었다 떨어진다 | `380ms` — 방석 언저리(거리의 `55%`)에서 시작해 칸의 `0.75` 배까지, 끝에 `6px` 낙하 |

**소리·진동은 팝의 정점(`PLACE_HIT_MS = 60ms`, 키프레임 25% 지점)에 맞춘다.** 커지는
구간을 짧게(60ms) 두고 가라앉는 구간을 길게 잡은 게 이것 때문이다 — 정점을 뒤로 밀면
그만큼 소리도 밀려 탭이 굼떠 보인다. 지연은 `setTimeout` 이 아니라 **오디오 그래프**에
맡긴다 (`Sfx.place(delay)`); `setTimeout` 은 프레임에 묶여 수십 ms 씩 밀리는데 60ms
지연에서는 그 오차가 그대로 어긋남이 된다.

**방석은 ✕ 메모·잠긴 칸에는 깔지 않는다.** ✕ 까지 방석을 받으면 "앉았다"는 신호가
흐려진다. 클리어 안무에서 토끼가 `hopCheer` 로 뛸 때도 방석은 제자리에 남는다 —
방석이 별개의 DOM 이라 토끼의 transform 을 따라가지 않기 때문이다.

**링·반짝임의 DOM 은 돌려 쓴다** (`Fx`, 슬롯 4벌 × 링 1 + 반짝임 4). 연타할 때 노드를
만들고 버리면 그 자체가 프레임을 잡아먹는다. 좌표는 슬롯 하나의 `transform` 으로만
옮기고 자식은 제자리에서 transform/opacity 만 움직인다 — 레이아웃이 없다. 벌마다
슬롯 전체를 `±30°` 안에서 돌려 같은 그림이 반복되는 걸 피한다.

> **연속 배치는 기다리지 않는다.** 슬롯이 4벌이라 연타해도 앞 연출을 뺏지 않고,
> 다 쓰면 가장 오래된 것부터 다시 쓴다 — 그 시점이면 그 연출은 이미 끝나 있다.
> 오답 판정(잠금·흔들림·시무룩 토끼)과 겹쳐도 서로 다른 칸에서 일어나고 연출이
> 짧아(0.3~0.38초) 부딪히지 않는다.
>
> 실측(CPU 6배 감속 = 보급형 안드로이드 수준, 13×13 판에서 13마리를 120ms 간격
> 연타): 프레임 중앙값 `16.7ms` · p95 `16.8ms`, `33ms` 를 넘긴 프레임 1개.
> **60fps 유지.** fxLayer 노드 수는 24개로 고정이다 (연타해도 늘지 않는다).

| `0` | **보드 물결** — 왼쪽 위부터 (행+열) 순서로 칸이 솟았다 가라앉는다. 칸 애니메이션 `340ms`, 칸 간격 `26ms`(판이 크면 총 `560ms` 안에 들어오도록 줄어든다) | 상승음, 진동 `12ms` |
| `물결끝 − 80` | **토끼 점프 + 색종이** — `hopCheer` `640ms`, 토끼 간격은 전부 뛰기 시작할 때까지 `560ms` 안에 들어오도록 (최대 `90ms`) | 상승 아르페지오, 진동 `12·12·24` |
| `점프 + 520` | **점수 카드** — 0 에서 최종 점수까지 `900ms` 카운트업 (ease-out cubic), 닿는 순간 숫자가 톡 | `90ms` 마다 작은 틱, 끝에 딩 + 진동 `14ms` |
| (다음 레벨) | **슬라이드** — 다 푼 판을 왼쪽으로 `200ms` 밀어내고 다음 판을 오른쪽에서 `340ms` 들여온다 | — |

13×13 판 기준 물결 `892ms` → 점프 `812ms` → 카드 `1332ms`. 5×5 판은 물결이 짧아
`548ms` → `468ms` → `988ms` 로 자동으로 당겨진다.

효과음은 오디오 파일 없이 **Web Audio 로 그때그때 생성**한다 (`Sfx`).
브라우저 자동재생 정책 때문에 AudioContext 는 첫 탭에서 깨운다.
HUD 의 스피커 버튼으로 끄고 켤 수 있고, 상태는 저장된다 — **음소거는 진동도 함께 끈다.**

`prefers-reduced-motion: reduce` 는 CSS 로 걷어내는 것만으로는 부족하다 — 순서를 세우는 건
JS 타임라인이라 그대로 두면 정지 화면을 1.3초 쳐다보게 된다. 켜져 있으면 물결·스태거를
건너뛰고 카드로 바로 간다.

## 튜토리얼

첫 실행이면 타이틀 대신 **고정 5×5 예제**로 바로 들어간다.
**읽지 않아도 배우게** 만드는 게 목표라, 설명은 보드 위 한 줄뿐이고 나머지는 전부 시각 요소다.

- **눌러야 할 칸 하나만** 밝게 pulse 하고 나머지는 어둡게 깔린다. 그 위에 손가락 아이콘이
  두 번 두드리는 애니메이션으로 떠 있다.
- **행동해야 진행된다.** 실제로 그 칸을 탭해서 토끼를 놓아야 다음 단계로 넘어간다.
- **틀린 칸을 눌러도 벌점이 없다.** 부드럽게 흔들려 거부하고, 정답 칸이 더 강하게 반짝인다.
- **규칙은 행동 직후에 보여준다.** 토끼를 놓는 순간 그 행·열에 빛줄기가 스윽 지나가고
  그 칸들이 차례로 ✕ 로 깔린다("이 줄엔 이제 못 와요"). 이어서 대각선 네 칸이 잠깐
  붉게 떴다 사라진다("대각선도 붙으면 안 돼요").
- 마지막 수를 놓으면 **"이제 진짜 시작!"** 연출과 함께 레벨 1 로 넘어간다.

건너뛰기 버튼은 항상 떠 있다. 예제는 해가 유일하고 5수 전부가 논리적으로 강제되는 수이며,
`tools/build.mjs` 가 빌드할 때마다 유일성과 각 단계의 정답 일치를 검증한다.
타이틀 → 게임 방법 → **튜토리얼 다시** 로 언제든 다시 볼 수 있다.

## 화면

- **타일형 보드** — 영역 경계선이 없다. 모든 칸이 독립 타일이고(모서리 20%, 간격 7%),
  영역 구분은 **오직 색으로만** 한다. 보드는 흰색 라운드 카드, 페이지는 웜 크림.
- **상단 HUD** — 뒤로가기 / 레벨 번호 + 난이도(당근 1~3개) / 설정
- **그 아래** — 토끼 배치 카운터(🐰 n/N), 점수, 목숨(당근 3개). **타이머 없음**
- **규칙 알약 칩 3개 상시 표시** — "색깔 자리마다 토끼 1마리" / "행·열마다 1마리" /
  "토끼끼리 붙기 금지" (좁은 화면에서는 문구를 줄바꿈해 그대로 보여 준다)
- **하단 플로팅 원형 버튼 2개** — 힌트(전구 + 남은 개수), 자동배치 부스터(발자국 + 남은 개수)
- 되돌리기 · 다시 놓기 · 확대/축소 · 소리 · 튜토리얼 다시는 **설정 시트**에 모아 두었다.

## 레벨 구조 — 스테이지 20판 + 무한 마당

앞의 **20판은 규칙을 익히는 구간**이다. 5×5 에서 10×10 까지 손으로 고른 순서로
올라가고, 마지막 두 판만 10×10 어려움이다. 20판을 모두 끝내면 **무한 마당**이
열린다. 21, 22, 23 … 끝이 없다.

스테이지를 20판에서 끊는 건 **11×11 이상은 무한 마당이 이미 더 잘하기 때문**이다.
손으로 고른 판은 개수가 정해져 있어서 언젠가 바닥나지만 무한 마당은 안 그렇고,
난이도도 구조 단계로 훨씬 촘촘하게 조절된다. 스테이지는 규칙을 가르치는 데까지만
맡는다.

> 스테이지에서 뺀 여섯 판(11×11 두 판 · 12×12 두 판 · 13×13 두 판)은 지우지 않고
> **`puzzles-retired.json`** 에 남겨 뒀다. 게임은 이 파일을 읽지 않지만
> `tools/build.mjs` 와 `tools/check-colors.mjs` 가 함께 검사한다 — 되돌리려고 남긴
> 데이터가 조용히 썩으면 남긴 의미가 없다.

무한 마당의 판은 **그때그때 만들어진다.** 미리 담아 둔 풀에서 꺼내 쓰지 않는 이유는
간단하다 — 풀은 언젠가 바닥나고, 바닥나면 같은 판이 다시 나온다.

핵심은 **레벨 번호 하나에 시드 하나를 못박아 둔 것**이다. 그래서

- 저장에는 "몇 번째 판인지"만 넣으면 된다 (판 자체를 들고 다니지 않아도 된다)
- 지웠다 다시 깔아도 27번 판은 여전히 27번 판이다
- 판이 무한히 이어지는데도 같은 판이 두 번 나오지 않는다

생성은 **웹 워커**에서 돌고, 지금 판을 푸는 동안 다음 판을 미리 만들어 둔다. 그래서
"다음 마당" 버튼을 눌렀을 때 기다리는 시간이 없다(실측 0.2초). 워커를 못 쓰는
환경(`file://` 등)에서는 메인 스레드에서 만들되 "새 마당을 만드는 중" 화면을 띄운다.

### 난이도 축은 크기가 아니라 구조다

한때는 난이도를 **판 크기**로 올렸다(12 → 13 → 14). 그 길은 막혀 있다.

- 세로 화면에서 한 칸이 14×14 는 24px 다(iPhone 14 기준). 이 게임은 **두 번 탭 =
  토끼 배치 = 즉시 판정**이라 오탭에 당근이 깎인다. 손가락 크기가 곧 난이도가 된다.
- 생성 시간이 크기에 지수적으로 는다.

그래서 **크기는 13 에서 멈추고**, 그 위로는 판의 구조만 조인다. 조이는 손잡이는
`structStep` 사다리 한 줄에 모아 뒀다.

| 단계 | 미니 영역 | 최소 칸수 | 추론 티어 | 첫 확정까지 |
| --- | --- | --- | --- | --- |
| 0 | 최대 3개 | 2 | T1 ~ T2 | — |
| 1 | 최대 1개 | 2 | T1 ~ T2 | — |
| 2 | 최대 1개 | 2 | T2 ~ T3 | — |
| 3 | 없음 | 2 | T2 ~ T3 | — |
| 4 | 없음 | 3 | T3 | — |
| 5 | 없음 | 3 | T3 | 2수 이상 (도전 판 전용) |

**1칸짜리 영역이 가장 큰 손잡이다.** 하나라도 있으면 T0(후보가 하나뿐인 그룹)가
첫 수부터 발화해서 판이 공짜로 시작한다. 그걸 없애는 것만으로 체감이 확 바뀐다.

**티어에 상한을 두는 것도 중요하다.** 하한만 걸면 11×11 에서도 T3 가 60% 나와서
27번이 60번보다 어려운 일이 생긴다.

커브는 이렇다. **크기가 오르는 구간에서는 구조를 한 눈금 내려** 숨을 틔운다.

| 레벨 | 구간 길이 | 판 크기 | 구조 단계 |
| --- | --- | --- | --- |
| 21 ~ 40 | 20판 | 11×11 | 0 |
| 41 ~ 65 | 25판 | 11×11 | 1 |
| 66 ~ 95 | 30판 | 12×12 | 1 ← 크기 업, 구조 유지 |
| 96 ~ 130 | 35판 | 12×12 | 2 |
| 131 ~ 170 | 40판 | 12×12 | 3 |
| 171 ~ 215 | 45판 | 13×13 | 2 ← 크기 업, 구조 다운 |
| 216 ~ 265 | 50판 | 13×13 | 3 |
| 266 ~ | — | 13×13 | 4 (커브의 끝 — 여기서 고정) |

**단계의 순서는 검증된 그대로 두고 구간 길이만 늘렸다.** 예전에는 네 판마다 한 눈금씩
올라가서 49번이면 벌써 커브의 끝이었다 — 스물아홉 판 만에 더 오를 데가 없어진다.
지금은 20판에서 시작해 구간마다 5판씩 길어지고, 커브의 끝은 **266번**이다.
초반이 짧은 건 새 요구를 빨리 만나 배우게 하려는 것이고, 뒤로 갈수록 긴 건 그 무렵이면
판 하나에 드는 시간 자체가 길어져 같은 판 수라도 훨씬 오래 머무르기 때문이다.

끝에 닿은 뒤로는 **더 조이지 않는다.** 무한히 어려워지는 커브는 결국 모두를 같은
벽 앞에 세운다. 그 뒤의 변화는 시드가 만드는 판 다양성과 도전 판이 담당한다.

**도전 판.** 10판마다(30, 40, 50 …) 구조 요구가 한 단계(70%) 또는 두 단계(30%)
높은 판이 온다. 어느 쪽인지는 레벨 번호에서 뽑으므로 30번은 언제나 같은 도전 판이다.
(첫 도전 판은 30번이라, 21~29 는 새 모드에 익숙해지는 구간이 된다.)
HUD 의 레벨 이름 옆에 `도전` 배지가 붙는다. 같은 도전 판에서 **3번 연속 게임오버면
같은 요구의 다른 시드**로 갈아탄다 — 판을 저장에 들고 다니지 않으려고, 막힌 횟수만
저장하고 거기서 시드를 유도한다(`(레벨, 재시도 횟수)` 가 같으면 판도 같다).

**못 만들었을 때.** 요구를 걸면 후보를 여러 개 버리게 되므로 예산을 넘길 수 있다.
그때는 ①구조를 딱 한 눈금 낮추고 ②그래도 없으면 요구에 못 미쳐도 만들어 둔 것을 쓰고
③최후에 판을 줄인다. 크기를 줄이는 게 제일 눈에 띄므로 맨 뒤에 둔다.
**빈손으로 끝나는 경우는 없어야 한다** — "새 마당을 만드는 중"에서 안 나오면 그게 곧 버그다.

그래서 예산의 **30%(최대 8초, 최소 2초)를 꼬리로 미리 떼어** ③에 남겨 둔다. 그리고 ③은
한 크기에 남은 시간을 통째로 주지 않는다 — 크기마다 절반씩 떼어 주고 후보 하나의 상한도
짧게 끊는다(13~12칸 `2.5초`, 11~10칸 `1.2초`, 그 아래 `0.6초`). 한 크기가 안 나올 때
다음 크기를 아예 못 보고 끝나는 걸 막기 위해서다. 남은 게 `1.5초` 아래로 떨어지면 중간
크기를 건너뛰고 곧장 9~10칸으로 간다 — 그 지점에서 목표는 예쁜 판이 아니라 판이 나오는 것이다.

> **고쳐진 버그.** 예전엔 꼬리가 25%·최대 5초였고 ③이 한 크기를 한 번 두드려 보고 끝났다.
> 그래서 13×13 **5단계**(도전 판) 중 후보가 유난히 안 나오는 시드(270번)를 **40초 이하**
> 예산으로 돌리면 **빈손으로 돌아왔다** — 60초에서는 35.5초에 요구대로 나오던 판이다.
> 지금은 같은 시드가 40초에 12×12, 12초에 10×10, **1초에도 9×9** 로 물러설지언정
> 빈손으로는 끝나지 않는다.

**예산별 물러섬 실측** (270번 = 13×13 5단계, 가장 안 나오는 시드):

| 예산 | 결과 |
| --- | --- |
| `90초` (실제 도전 판 예산) | 13×13 5단계, 요구 그대로 — `35.6초` |
| `60초` | 13×13 5단계, 요구 미달 채택(T2) |
| `40초` / `18초` | 12×12 로 축소 |
| `12초` | 10×10 로 축소 |
| `6초` / `3초` / `1초` | 9×9 로 축소 — **빈손 0건** |

**커브 구간별 생성 시간 실측** (Node, 프리페치 예산 60초 기준. 도전 판은 실제 게임에서
90초를 받으므로 아래 값보다 여유가 있다):

| 구간 | 표본 | 중앙값 | 최대 |
| --- | --- | --- | --- |
| 11×11 (21~65) | 6판 | `0.9초` | `3.6초` |
| 12×12 (66~170) | 12판 | `0.4초` | `17.4초` |
| 13×13 2~3단계 (171~265) | 8판 | `12.9초` | `35.9초` |
| 13×13 4단계 (266~, 커브의 끝) | 7판 | `16.9초` | `21.3초` |
| 13×13 5단계 (도전 판) | 5판 | `28.8초` | `43.8초` |

> 43개 레벨 전수에서 유일해·논리 완주·영역 연결·규칙 위반은 **0건.** 60초 예산으로
> 요구한 단계에서 물러선 건 2판(230·300 — 둘 다 도전 판)이고, **실제 도전 판 예산인
> 90초로 다시 재면 300번은 45.5초에 요구대로 나온다** (230번은 53.4초에 한 눈금 물러섬).

> 이 커브는 `t = 레벨 - ENDLESS_START` 로 정의돼 있어서, 스테이지가 26판에서
> 20판이 되며 시작 번호가 27 → 21 로 내려갔을 때 표의 번호만 밀렸다.

> **유일해 보장.** 무한 마당의 판도 스테이지판과 똑같이 "해가 정확히 하나 + 찍기 없이
> 논리만으로 풀림"을 만족한다. 생성기가 **게임의 힌트 엔진(`runLogic`)을 그대로**
> 판정에 쓰기 때문이다 — 생성기가 자기 솔버를 따로 가지면 두 솔버가 언젠가 갈라지고,
> 그러면 "힌트로 끝까지 풀리는 판"이라는 보장이 깨진다. 채택 직전에 `findSolutions` 로
> 해가 하나뿐인지 한 번 더 확인한다.

## 힌트 · 자동배치 — 전역 재화

판마다 3개/2개로 리셋되지 않는다. **계정 하나에 하나뿐인 보유량**이고 판을 넘어 유지된다.

- 최초 실행에 힌트 3개 · 자동배치 2개 지급
- 쓰면 줄고, 판이 바뀌어도 그대로
- 떨어지면 버튼이 **"광고 보고 충전"** 으로 바뀐다 (잠기지 않는다 — 눌렀을 때 충전으로
  이어지는 게 그 버튼의 다음 할 일이므로)
- 충전 성공 시 힌트 3개 또는 자동배치 2개

광고는 `showRewardedAd(kind)` 어댑터 함수 **하나**로 추상화되어 있다. 게임 쪽은
"`Promise<boolean>` 을 돌려주는 함수"라는 것 외에는 아무것도 모른다.

> ⚠️ **지금 구현은 임시다.** 실제 광고가 아니라 **3초 카운트다운 모달**로 대신한다.
> 웹 단계에서 충전 흐름 자체를 만들어 두려는 목적이고, 앱인토스 탑재 시점에
> **이 함수 본문만 SDK 호출로 갈아끼우면 된다.** 다른 곳은 손댈 필요가 없다.

## 점수

판 크기와 **남은 당근**이 기본이고, **이 판에서 쓴** 힌트·자동배치만큼 깎는다.
시간은 보지 않는다 (그래서 타이머도 없다).

```
점수 = 칸 수 × 10  +  남은 당근 × 150  −  쓴 힌트 × 100  −  쓴 자동배치 × 60      (최소 0)
만점 = 칸 수 × 10  +  당근 3개 × 150
```

예전에는 "남은 힌트 개수"를 **더했다.** 힌트가 전역 재화가 된 지금 그 식을 그대로 두면
지갑이 두둑한 사람이 같은 판을 같은 실력으로 풀어도 점수가 높아진다. 점수는 지갑이 아니라
**이 판에서 한 일**만 봐야 하므로 가산에서 감점으로 뒤집었다.

상단 HUD 에 실시간으로 표시되고, 클리어 화면에서 0 부터 카운트업된다. 스테이지는 레벨별
최고 점수가, 무한 마당은 전체 최고 점수가 저장된다. 한 번도 안 틀리고 힌트·자동배치도
안 쓰면 **만점**이다.

## 색 배정

팔레트는 **"토끼네 마당" — 봄 텃밭의 자연색 14가지**다.
새싹 연두 · 서리 연하늘 · 볏짚 노랑 · 진달래 핑크 · 맑은 하늘 · 라일락 · 호박 주황 ·
이끼 세이지 · 감 로즈 · 물총새 청록 · 흙 브라운 · 자두 보라 · 진한 잎초록 · 밤바다 남색.
채도는 부드럽게 누르되 **명도는 확실히 벌려** 두었다.

적록색약이 있으면 초록·노랑·주황·빨강이 전부 노란 계열로 뭉개지므로, 그 색들이
**밝기 사다리** 위에 흩어져 있어야 층으로라도 갈린다. 하늘·라일락은 파랑 계열이라
적록색약에서도 색상 자체가 남는다.

색 수는 **가장 큰 판의 영역 수(13)보다 많아야 한다.** 색이 모자라면 서로 다른 두 영역이
같은 색을 쓰게 되는데, 이 게임은 "한 영역에 토끼 하나"가 규칙이라 영역을 못 가르는 건
보기 나쁜 정도가 아니라 **풀 수 없게 되는** 문제다. 떨어져 있는 같은 색 두 덩어리를 보고
플레이어는 그게 한 영역인지 두 영역인지 알 방법이 없다. 여유를 만들 수 있는 방향은
차가운 쪽뿐이었다 — 따뜻한 파스텔 구역은 색약 시야에서 이미 빽빽하다.

영역 색은 고정이 아니라 **레벨마다 그래프 컬러링으로 배정**된다. 규칙은 세 겹이다.

1. **색은 영역마다 하나씩, 겹치지 않게** (영역 수 ≤ 팔레트 크기인 동안은 항상)
2. **변을 맞댄 영역**끼리는 색약 시야를 포함해 ΔE 가 확실히 벌어져야 한다 (SAFE_DE = 20)
3. **모서리만 스친 영역**끼리도 같은 색은 금지 — 대각으로 이어진 한 덩어리로 보인다

이웃이 많은 영역부터 남은 색 중 가장 멀리 떨어진 것을 집고, 그다음 "색 바꾸기 / 두 영역의
색 맞바꾸기"로 **가장 약한 이웃 쌍의 거리를 최대화**하는 방향으로 다듬는다. 정원을 깨지
않는 이동만 쓰므로 다듬는 동안 1) 이 유지된다. 판이 팔레트보다 커지면 1) 만 양보하고,
그때도 같은 색끼리는 최대한 멀리 떼어 놓는다.

`node tools/check-colors.mjs` 가 모든 레벨에서 이 셋을 확인한다 (현재 최약 인접 ΔE = 25.3).

색 거리는 단순 RGB 차이가 아니라 **Lab 공간의 ΔE**로 재고, 정상 시야뿐 아니라
**적록색약(2형·1형) 시뮬레이션 결과까지 계산해 그중 가장 가까워지는 값**을 그 쌍의
거리로 삼는다. 즉 색약이 있어도 구분되는 조합만 이웃으로 배정된다.

> 청황색약(tritan)은 파랑–노랑 축이 무너지는데, 그 축은 적록색약이 유일하게 보존하는
> 축이기도 하다. 파스텔 명도 범위 안에서 둘을 동시에 만족시킬 수 없어, 훨씬 흔한
> 적록 쪽(남성 약 8%)을 택했다. 청황색약은 0.01% 수준이고, 영역 경계선이 색과
> 무관한 구조 단서로 남는다.

여기에 더해 **모든 칸에 옅은 격자선**을 깔아 영역 안에서도 칸 단위가 항상 읽히게 했고,
영역 경계는 그보다 조금 굵은 선으로 형태만 잡아준다.

## 레벨 다시 만들기

생성(느림)과 레벨 순서 결정(빠름)이 분리돼 있다. 커브만 바꿔 다시 돌리는 건 순식간이다.

```bash
node tools/generate-puzzles.mjs      # 퍼즐 풀 생성 -> puzzles-pool.json (오래 걸린다)
node tools/curate-levels.mjs         # 풀에서 레벨 순서 결정 -> puzzles.json
node tools/build.mjs                 # 검증 + index.html 내장 사본 갱신
node tools/check-colors.mjs          # 영역 배색 검증
node tools/check-generator.mjs       # 무한 마당 생성기 검증
```

생성기는 다음을 **모든 레벨에 대해 보장**한다.

> **주의 — 스테이지판은 전부 tier 1 이다.** 생성기의 논리 솔버에 T2·T3
> 추론을 한 번 두고 곧장 멈추는 버그가 있었고(`progress` 를 세우지 않아 루프가 끝났다),
> 그래서 T2 이상이 필요한 판이 전부 "논리로 안 풀림"으로 버려졌다. 지금은 고쳤지만
> 기존 스테이지판의 metrics 는 버그가 있던 시절에 매겨진 값이다 (판 자체는 멀쩡하다 —
> 오히려 더 쉬운 쪽으로만 걸러졌다). 다시 생성하면 T2·T3 판도 나온다.
> 게임 안 힌트 엔진(`runLogic`)에는 이 버그가 없었고, 무한 마당은 그쪽을 쓴다.

1. 해가 **정확히 하나** — 무작위로 영역을 키운 뒤, 가짜 해가 나오면 칸 하나의 소속 영역을
   바꿔 그 해를 깨뜨리는 수선(repair) 과정을 반복한다. 정답 칸은 절대 옮기지 않고
   난이도 프로필(min/max)도 매 수선마다 검사하므로, 정답과 난이도 규칙이 함께 유지된다.
2. **찍기 없이 논리만으로 풀린다** — 규칙 T0~T3 로 끝까지 풀리지 않으면 채택하지 않는다.
   덕분에 힌트가 어느 상황에서도 막히지 않는다.
3. 모든 영역은 **상하좌우로 연결**돼 있다.

`tools/build.mjs` 는 생성기와 독립적으로 유일성·연결성·난이도 규격·튜토리얼을 다시
검사하므로, `puzzles.json` 을 손으로 고친 경우에도 안전망이 된다.

### 레벨 커브

`curate-levels.mjs` 가 풀에서 고른다. 쉬움의 기준은 추론 수(적을수록 쉬움),
1칸 영역 개수(많을수록 쉬움), 첫 확정까지의 수, 가장 큰 영역 크기(작을수록 눈이 편함).

- **첫 5레벨은 5×5 중에서도 가장 쉬운 것들** — 전부 추론 5수, 막히는 구간 0, 1칸 영역 2개
- 그 뒤로는 크기 순으로 올라가되, 같은 크기 안에서는 쉬운 것부터
